Clusters and Applications¶

The ApplicationSet policystack in openshift-gitops on the hub creates one Argo CD Application per element for every managed cluster that has a fleet file. The fleet file picks the Git revision and the values files. The template is install/templates/appset.yaml.

A second ApplicationSet, policystack-lifecycle, creates one Application per fleet file that names this hub in hub, or a managed hub it builds for (Global Hub). That Application builds or destroys the cluster (Cluster lifecycle). Its template is install/templates/lifecycle.yaml.

Fleet files¶

A fleet file declares one cluster. A managed cluster's file is fleet/<cluster>.yaml, named exactly like its ManagedCluster. The hub's file is fleet/hubs/<hubName>.yaml (The hub).

Key Required Effect
revision Yes Branch, tag or commit SHA every Application for the cluster renders from (Revision).
valueFiles No Paths under values/, lowest precedence first. Each entry adds that file to the cascade (Order).
hub No hubName of the hub that builds the cluster. Without it the cluster must be imported (Cluster lifecycle).
state No present (default) or absent. absent destroys the cluster (Destroy). Requires hub.
install No The cluster to build (Fleet keys). Requires hub.
version No OpenShift release, x.y.z, the cluster runs. Bumping it upgrades the cluster (Upgrades). Required with hub.
channel No Upgrade channel, such as stable-4.20 (Upgrades).

No other keys are allowed. A hub's own file cannot set hub, state or install, and hub must name a hub that has a file in fleet/hubs/. The Day-2 ApplicationSet ignores the three lifecycle keys. version and channel go only in the fleet file, never in a values layer, so the clusters an upgrade moves are the fleet files it changes. Argo CD reads fleet files as YAML 1.1, so revision, version and channel must be YAML strings. Quote one YAML reads as a number or a boolean: "1.10", "20261003", "on". Unquoted, revision: 1.10 pins 1.1. The validator checks these rules and that every valueFiles entry is a file (Validation).

# fleet/prod-east-1.yaml
revision: main
valueFiles:
  - environments/prod.yaml
  - datacenters/dc1.yaml
  - platforms/aws.yaml

Any file under values/ can be listed. tenants/payments.yaml is a custom layer: add the file and list it where it should rank. An old config.<baseDomain>/<category>.<priority>: <value> label becomes the entry <category>s/<value>.yaml, placed in priority order.

Upstream ships no live fleet files, since a shipped file would configure a real cluster as soon as someone installs from upstream. The examples are the validator's fixtures in tools/validator/testdata/clusters/: prod-east-1.yaml, nonprod-west-1.yaml, hubs/acm-dc1.yaml, and the hub-built hcp-kubevirt.yaml, hcp-agent.yaml, hcp-retired.yaml, hive-aws.yaml, hive-retired.yaml, sno-edge.yaml and sno-retired.yaml.

The ApplicationSet reads fleet files only from the repo's default branch, as HEAD. Copies of fleet/ on other branches have no effect. Changing the default branch re-points every cluster to the fleet files on the new branch, and a cluster without one there loses its Applications.

Fleet changes reach Argo CD within about 6 minutes: the ApplicationSet controller re-runs its generators every 3 minutes, and Argo CD caches the commit a branch points to for 3 minutes. An ApplicationSet webhook makes changes immediate, except the fix for a failed generation, which still waits for the 3 minute retry.

PolicyStack still reads five labels. ACM sets the first four, and nobody sets them by hand:

Label Set by Effect
clusterID ACM, on OpenShift clusters Selects the cluster's Argo CD secret and becomes selectedId. A cluster without it gets no Applications.
local-cluster ACM, on the hub Switches the cluster to the hub's fleet file and names it by hubName (The hub).
name ACM The ManagedCluster name. The Placement selector matches on it (Placement).
apps.open-cluster-management.io/cluster-name ACM's GitOpsCluster, on the cluster secret Matches a fleet file's hub to a default-mode managed hub (Lifecycle generator).
global-hub.open-cluster-management.io/deploy-mode You, when importing a managed hub into a Global Hub default switches the managed hub to its hub file, fleet/hubs/<cluster>.yaml, and lets this hub build its clusters (Global Hub).

Revision¶

revision is a branch, a tag or a commit SHA. Branch names with / work.

If a fleet file this hub reads does not parse, has no revision, or pins a revision that does not exist, ApplicationSet generation fails. Argo CD then creates, updates and deletes no Applications for any cluster until the file is fixed. The ApplicationSet's ErrorOccurred condition holds the error:

oc get applicationset policystack -n openshift-gitops \
  -o jsonpath='{.status.conditions[?(@.type=="ErrorOccurred")].message}'

A fleet file that does not parse stops policystack-lifecycle the same way, so the hub creates, upgrades and destroys no cluster until it is fixed. A bad revision there breaks only that cluster's lifecycle-<cluster> Application. Check it with the same command on policystack-lifecycle.

Pin tags, commit SHAs, protected branches, or a branch you keep until its pin moves off. A pinned branch that is deleted freezes the whole fleet, and GitHub deletes a pull request's branch on merge when automatic deletion of head branches is on.

The generator reads HEAD rather than main, so it follows a rename of the default branch.

The Render Diff comment on a PR shows each cluster's Policies at its revision before and after the merge.

The hub¶

The hub's own ManagedCluster carries ACM's local-cluster label. Its fleet file is fleet/hubs/<hubName>.yaml, where hubName is an install chart value set once per hub, with no default (The install chart). A Global Hub managed hub imported in default mode has no local-cluster, so the global hub reads its file for it (Global Hub).

# fleet/hubs/acm-dc1.yaml
revision: main
valueFiles:
  - environments/prod.yaml
  - datacenters/dc1.yaml
  - platforms/baremetal.yaml
  - acm/acm-dc1.yaml

On the hub, hubName replaces the ManagedCluster name everywhere: the Applications are <element>-<hubName>, the cluster values file is values/clusters/<hubName>.yaml, and selectedName is hubName. Changing hubName renames the hub's Applications and every object they render. Hubs in the same datacenter share files such as acm/acm-dc1.yaml by listing them.

hubName is a chart value because nothing on the hub gives it a stable, unique name:

  • Every hub's own ManagedCluster is named local-cluster by default, so the cluster name cannot tell two hubs reading this repo apart.
  • ACM's localClusterName (ACM 2.14 and later) changes only at install, or after turning off hub self-management.
  • OpenShift's clusterID is a UUID that changes when a hub is rebuilt.

So each hub's identity is set once in its install release, and its configuration stays in Git. helm get values policystack -n openshift-gitops shows a hub's hubName. hubs/ is a subdirectory so a hub's file cannot collide with a managed cluster of the same name.

Every hub reading the same repo, including a passive or disaster recovery hub, sets its own hubName at helm install (Install PolicyStack). The chart fails without it, rather than apply another hub's configuration. Upgrades reuse the stored value.

Protection¶

PolicyStack reads no other labels. Short of editing the five labels above, which RBAC on ManagedClusters and on Secrets in openshift-gitops guards, oc label cannot change what a cluster runs. Whoever can merge to fleet/ on the default branch decides it instead. The repo ships no CODEOWNERS file, because owners differ per fork. Add:

  • A CODEOWNERS entry for /fleet/.
  • A ruleset on the default branch that requires a pull request with code owner review, and blocks force pushes and deletion.
# .github/CODEOWNERS
/fleet/ @<org>/<team>

To require code owner review only for production clusters, own /fleet/prod-*.yaml and /fleet/hubs/ instead of /fleet/.

The same review guards cluster creation and destruction: a merged state: absent destroys the cluster (Destroy).

Generators¶

The generator, as rendered with hubName=acm-dc1:

generators:
  - matrix:
      generators:
        - matrix:
            generators:
              - clusters:
                  selector:
                    matchExpressions:
                      - key: clusterID
                        operator: Exists
              - git:
                  repoURL: 'https://github.com/PolicyStack/PolicyStack.git'
                  revision: HEAD
                  pathParamPrefix: fleet
                  files:
                  - path: 'fleet/{{if index .metadata.labels "local-cluster"}}hubs/acm-dc1{{else if eq (index .metadata.labels "global-hub.open-cluster-management.io/deploy-mode") "default"}}hubs/{{.name}}{{else}}{{.name}}{{end}}.yaml'
        - git:
            repoURL: 'https://github.com/PolicyStack/PolicyStack.git'
            revision: '{{.revision}}'
            directories:
            - path: 'stack/*'
  1. A clusters generator. Every Argo CD cluster secret with a clusterID label.
  2. A git files generator. The cluster's fleet file at HEAD, fleet/hubs/<hubName>.yaml on a cluster labeled local-cluster, fleet/hubs/<cluster>.yaml on a managed hub labeled deploy-mode=default, and fleet/<cluster>.yaml otherwise. The file's keys become parameters. pathParamPrefix: fleet moves the file's path parameters under fleet, because a matrix keeps the first child's value when two children set the same parameter, and the file's path would otherwise replace the directory's.
  3. A git directories generator. Every directory under stack/ in gitRepo, at the fleet file's revision.

The inner matrix pairs each cluster with its fleet file. A cluster without one pairs with nothing. The outer matrix pairs each cluster with the directories, and each cluster and directory pair becomes one Application. The directory list comes from the cluster's own revision, so an element added on one branch reaches only clusters on a revision that contains it. Every directory gets an Application whether the element is enabled or not. A disabled element renders no objects.

The GitOpsCluster from Install PolicyStack creates one cluster secret per managed cluster. Clusters without a fleet file are imported but get no Applications.

Lifecycle generator¶

policystack-lifecycle has two generators, as rendered with hubName=acm-dc1:

generators:
  - matrix:
      generators:
        - clusters:
            selector:
              matchExpressions:
                - key: local-cluster
                  operator: Exists
        - git: &fleet
            repoURL: 'https://github.com/PolicyStack/PolicyStack.git'
            revision: HEAD
            files:
            - path: 'fleet/*.yaml'
            - path: 'fleet/*/*.yaml'
              exclude: true
          selector:
            matchExpressions:
              - key: hub
                operator: In
                values:
                  - "acm-dc1"
  - matrix:
      generators:
        - git: *fleet
          selector:
            matchExpressions:
              - key: hub
                operator: Exists
        - clusters:
            selector:
              matchLabels:
                apps.open-cluster-management.io/cluster-name: '{{ if regexMatch "^[a-z0-9]([-a-z0-9]{0,61}[a-z0-9])?$" (toString .hub) }}{{ .hub }}{{ end }}'
                global-hub.open-cluster-management.io/deploy-mode: default

Both read every fleet file at HEAD. Argo CD's default globbing lets * match /, so fleet/*.yaml also matches files in subdirectories, and the exclude entry drops them: the hub files and anything else under a subdirectory, which neither ApplicationSet nor the validator reads. A file without hub never matches, so imported clusters get no lifecycle Application.

  1. The hub's own clusters. The selector keeps files whose hub is this hub's hubName, paired with the hub's own cluster secret. A hub that does not manage itself has none and builds nothing.
  2. Clusters of default-mode managed hubs (Global Hub). Each file with hub is paired with the cluster secret of the ManagedCluster it names, if that cluster is a managed hub imported in default mode. The fleet files come first because Argo CD templates a child generator's fields but not its selector. A hub that is not a DNS label matches nothing, since as a label value it would fail the whole ApplicationSet.

The cluster secret supplies .name, the ManagedCluster the Policies are placed on.

Applications¶

Field Value
Name <element>-<cluster>, or <element>-<hubName> on a cluster labeled local-cluster
Project default
Source stack/<element> in gitRepo at the cluster's revision, rendered by Helm with the values cascade
Destination The hub, https://kubernetes.default.svc, namespace open-cluster-management
Sync Automated with prune, selfHeal and allowEmpty, sync option RespectIgnoreDifferences=true

<element> is the directory name and <cluster> the ManagedCluster name. Argo CD uses the Application name as the Helm release name, and every rendered object name derives from it (Rendered objects, Naming limits).

Argo CD deploys only to the hub. ACM delivers the policies to the managed clusters (Placement). The chart sets policyNamespace on every object it renders, so the destination namespace is unused.

allowEmpty lets automated sync prune a disabled element down to no objects (Disabling an element).

policystack sets preserveResourcesOnDeletion: false, so its Applications carry the resources finalizer and deleting one deletes its objects on the hub (Removing an element). Removal stays bounded:

  • A failed render prunes nothing. The Application reports a ComparisonError and keeps its objects.
  • A failed generation deletes nothing. The ApplicationSet changes no Application until it is fixed (Revision).
  • The destination is always the hub, so Argo CD deletes only hub objects. ACM then removes the policies from the managed cluster (What happens on the managed cluster).

ACM copies each Policy into the cluster's namespace on the hub. From policy-library 3.1.0 the chart sets copyPolicyMetadata: false, so the copies carry no Argo CD tracking labels or annotations, and Argo CD never prunes them. Clusters pinned to a revision with an older chart pin still copy the metadata until their pin moves.

The lifecycle Applications differ:

Field Value
Name lifecycle-<cluster>, where <cluster> is the fleet file name
Source lifecycle/ in gitRepo at the fleet file's revision, with the same cascade (Order)
Destination The hub, namespace open-cluster-management
Sync Automated with prune and selfHeal

policystack-lifecycle also sets preserveResourcesOnDeletion: false. Deleting a lifecycle Application deletes its Policies, and the cluster keeps running unmanaged (Abandon).

Injected values¶

Each Application passes these keys to Helm in valuesObject, built from the cluster's ACM labels and hubName. Order gives their precedence over the values files.

Key Value
selectedName The cluster name, or hubName on the hub.
selectedId The clusterID label.
selector.matchExpressions A map with one In expression on the name label, under the key name.
version, channel The fleet file's keys, only when it sets them.

Elements can read every key. The policy-library chart turns selector into each Placement's cluster selector (Placement). On the hub, selectedName is hubName, but the name expression holds the hub's ManagedCluster name. An element that needs a fact such as the environment reads a key that the matching values file sets. For prod-east-1:

selectedName: prod-east-1
selectedId: <clusterID>
selector:
  matchExpressions:
    name:
      key: name
      operator: In
      values:
        - "prod-east-1"

A lifecycle Application passes selector.matchExpressions.hub, one In expression on the name label holding the name of the hub's ManagedCluster the Policies apply to, and the fleet file's own keys: hub, state (default present), version and channel when set, and install (default {}). They rank above every values file, so the fleet file's install overrides the cascade (Values).

The install chart¶

The install chart installs both ApplicationSets, the cluster import into Argo CD and its RBAC (Install PolicyStack). Its values:

Value Set in Use
gitRepo --set at helm install The repository the git generators read and every Application renders from. Required.
hubName --set at helm install Names this hub's fleet file, fleet/hubs/<hubName>.yaml, its Applications and its cluster values file. Selects the fleet files whose hub this hub builds. Unused on a default-mode Global Hub managed hub (Global Hub). Required (The hub).
policyNamespace install/values.yaml The namespace the chart creates. Elements read the same value from the root values.yaml, and CI checks the two match. Do not change it.

helm upgrade --reset-then-reuse-values keeps gitRepo and hubName. To see the ApplicationSets as Argo CD gets them:

helm template policystack ./install --set hubName=acm-dc1 --set gitRepo=https://github.com/PolicyStack/PolicyStack.git
